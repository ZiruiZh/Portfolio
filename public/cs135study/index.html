;; L01

Values and expressions

The model of computation starts here: numbers, prefix expressions, and rewriting an expression one small step at a time until only a value is left.

You should know

  • Exact numbers Nat, Int, Rat and how they relate as subtypes
  • Writing maths in prefix notation
  • Evaluating expressions with substitution steps
  • Defining constants with define
  • + - * / quotient remainder sqr expt, plus max and min
  • < > = <= >= and Bool expressions with true false and or not

  • Nat (natural numbers): 0, 1, 2, 3, … 0 is a Nat in this course. Defined recursively: 0 is a Nat; if n is a Nat then n + 1 is a Nat. (That definition is exactly why the recursion template in L04 works.)
  • Int: …, −2, −1, 0, 1, 2, …
  • Rat: any fraction p/q. Racket keeps these exact: (/ 1 3) produces 1/3, never 0.333…
  • Subtypes: Nat ⊆ Int ⊆ Rat (and from L02, Rat ⊆ Num). Every Nat is an Int, every Int is a Rat. A function whose contract says it consumes a Rat automatically accepts Ints and Nats; one that consumes a Nat does not promise to work on −3 or 1/2.
  • Exact numbers can be arbitrarily large (limited only by memory): (expt 2 100) is computed exactly.
  • 3/2 is a number (one and a half). (/ 3 2) is an expression that evaluates to that number. DrRacket may print it as a mixed fraction.
Shortcut

In the teaching languages, decimal literals are exact too: 1.5 is exactly 3/2 and (* 1.5 2) is 3. Only results marked #i are inexact (see L02).

Trap

Dividing Nats does not give a Nat. (/ 7 2) is 7/2. So the contract for an average is -> Num (or Rat), never -> Nat. Classic quiz question: "Is −3 a Nat? Is 4 a Rat? Is 3/2 an Int?" (No, yes, no.)

Racket puts the operator first and wraps every application in parentheses: infix (6 / 2) · (1 + 2) becomes (* (/ 6 2) (+ 1 2)). Prefix needs no order-of-operations rules because the parentheses say everything.

Steps: infix to prefix
  1. Fully bracket the infix expression using BEDMAS so each pair of brackets holds exactly one operator. Implicit multiplication like 2(1+2) becomes an explicit ·.
  2. Inside each bracket, move the operator to the front: (a op b) → (op a b).
  3. Rename: · or × → *, ÷ → /, x² → (sqr x), xy → (expt x y), √x → (sqrt x), |x| → (abs x).
  4. Optional: merge chains of the same operator, since + * accept many arguments: (+ (+ a b) c) → (+ a b c).
;; 3x² − 2x + 7            with x defined
;; ((3 · x²) − (2 · x)) + 7
(+ (- (* 3 (sqr x)) (* 2 x)) 7)

;; 6 ÷ 2(1 + 2)  →  ((6 / 2) · (1 + 2))
(* (/ 6 2) (+ 1 2))        ⇒ 9
  • + * / need at least two arguments here: (+ 72) is an error ("expects at least 2 arguments").
  • - with one argument negates: (- 144) ⇒ -144, (- -21) ⇒ 21.
  • Many arguments work left to right: (- 10 1 2) ⇒ 10 − 1 − 2 = 7; (/ 720 5 4 3 2 1) ⇒ 6.
Trap

An open parenthesis always means "apply the thing after me". (5) and ((+ 1 2)) are errors: "expected a function after the open parenthesis". Never add brackets "for safety" the way you might in maths.

Evaluation is rewriting. Each step (written ⇒) replaces one subexpression with its value, and the result is always a valid, simpler program. You stop when you reach a value.

Steps: one substitution step
  1. Scan from the left for the first subexpression that has no parentheses inside it, so every argument is already a value.
  2. Replace that whole subexpression with its value. That is one step, even if the operator has many arguments: (+ 11 12 13) ⇒ 36.
  3. Copy everything else unchanged. Repeat.
(- (+ 9 (* (/ 6 (+ 1 1)) 3)) 2)
⇒ (- (+ 9 (* (/ 6 2) 3)) 2)
⇒ (- (+ 9 (* 3 3)) 2)
⇒ (- (+ 9 9) 2)
⇒ (- 18 2)
⇒ 16
Trap

Only one rewrite per step, leftmost first. (+ (* 2 3) (* 4 5)) ⇒ (+ 6 (* 4 5)) ⇒ (+ 6 20) ⇒ 26. Writing (+ 6 20) as the first step loses marks on a "show every step" question.

Shortcut

Values never step: numbers, true/false, symbols, characters, strings, empty, and lists made only of values like (cons 1 empty) or (list 1 2).

(define hours-in-day 24)
(define minutes-in-day (* hours-in-day 60))   ; evaluated once: 1440
  • (define name expr) evaluates expr to a value first, then binds that value to name. In Racket these are called constants, not variables, because they never change.
  • A name must be defined before it is used (error: "x is used here before its definition").
  • A name can't be re-defined (error: "this name was defined previously and cannot be re-defined"). This includes using one name for both a constant and a function.
  • Give meaningful numbers a name instead of leaving "magic numbers" in code (freezing, feet-in-mile).
  • Identifier rules (L02): letters, digits and characters like - _ . ? = !; no spaces, brackets or quote marks; at least one non-digit. 2d, x-ray, ? and hello! are all valid names.

Relationship to remember: n = d · (quotient n d) + (remainder n d). quotient and remainder on a Rat such as 3/2 is an error ("expects an integer").

Shortcut: digit and divisibility tricks
  • Last digit of n: (remainder n 10). Drop the last digit: (quotient n 10). Tens digit: (remainder (quotient n 10) 10).
  • Is n divisible by d: (zero? (remainder n d)). Even: (zero? (remainder n 2)), or even? from L07.
  • Minutes to hours and minutes: (quotient m 60) and (remainder m 60).
  • Clamp x into [lo, hi]: (max lo (min hi x)).
Trap

You may compute with (quotient n 10), but you may not recurse on it. The Rules for Recursion only allow (sub1 n) for a Nat (see L04).

  • (< x 5) is a question ("is x less than 5?") that evaluates to true or false. It does not state a fact about x like it does in maths.
  • < > = <= >= compare numbers only. (= 'a 'a) is an error. Each type has its own equality: symbol=? (L03), char=? and string=? (L12).
  • Bool has exactly two values: true and false.
  • and is true when every argument is true; or is false when every argument is false; not flips one Bool. and/or need at least two arguments.
  • Arguments must be Bools: (and 1 true) is an error ("question result is not true or false").

Short-circuit evaluation

and stops at the first false and or stops at the first true; the remaining arguments are never evaluated.

(and (or (< 2 3) (> 1 5)) (not (< 10 15)) (<= 5 5))
⇒ (and (or true (> 1 5)) (not (< 10 15)) (<= 5 5))
⇒ (and true (not (< 10 15)) (<= 5 5))      ; or hit a true: done
⇒ (and true (not true) (<= 5 5))
⇒ (and true false (<= 5 5))
⇒ false                                       ; (<= 5 5) never evaluated
Shortcut: the guard pattern

Put the safety check first so the risky part only runs when it is safe: (and (cons? lst) (symbol=? (first lst) 'a)) never calls first on an empty list; (and (not (zero? d)) (> (/ n d) 1)) never divides by zero.

De Morgan's laws

(not (and A B))  ≡  (or (not A) (not B))
(not (or A B))   ≡  (and (not A) (not B))
;; then push not into comparisons:
(not (< a b)) ≡ (>= a b)      (not (> a b)) ≡ (<= a b)
On the exam

Simplify (not (or (< x 3) (> x 9))) → (and (>= x 3) (<= x 9)). Or show each substitution step of a Bool expression, stopping exactly where short-circuiting kicks in.

Shortcut

Comparisons accept more than two arguments: (<= 0 x 10) means 0 ≤ x ≤ 10. The slides only show the two-argument form, so (and (<= 0 x) (<= x 10)) is the safe way to write it on an exam.

Functions

User-defined functions, the formal substitution rules that give programs their meaning, and inexact numbers.

You should know

  • Defining functions with define, and applying them
  • Predicates and the ? naming convention
  • The formal substitution rules for built-ins, Bool operators and user-defined functions
  • Inexact numbers and Nat vs Int vs Rat vs Num
  • Math functions abs acos asin atan cos exp log sin sqrt tan, constants e pi, predicates number? and inexact?
  • How to format an assignment submission

;; f(x) = x² + 3x + 4
(define (f x) (+ (* x x) (* 3 x) 4))
;; g(x, y) = x² + 6xy + y² + 9x − 3y − 100
(define (g x y)
  (+ (sqr x) (* 6 x y) (sqr y) (* 9 x) (- (* 3 y)) -100))
(check-expect (f 2) 14)
(check-expect (g 2 3) -42)

A definition has three parts: a name, a list of parameters, and exactly one body expression. Shape: (define (name p1 p2 …) body).

  • Renaming parameters consistently changes nothing: (define (f x) (* x x)) behaves like (define (f z) (* z z)).
  • Different functions may reuse the same parameter names.
  • Parameter order matters: (define (h x y) (- x y)) and (define (h y x) (- x y)) are different functions.
Trap

Calling with the wrong number of arguments is an error. A function name without parentheses around it is not a call; in our language, using a function name on its own is an error.

Steps
  1. Evaluate the arguments, left to right, until every argument is a value. Don't touch the function yet.
  2. In one step, replace the whole application with the function's body, substituting each argument value for every occurrence of its parameter.
  3. Keep evaluating the body.
(define (h x y) (+ x x x y))
(h (+ 4 6) 9)
⇒ (h 10 9)              ; argument first
⇒ (+ 10 10 10 9)        ; ALL three x's replaced in a single step
⇒ 39

When several applications are ready, pick the leftmost, and only apply a user-defined function once all its arguments are simple values.

A predicate is a function that produces a Bool. By convention its name ends in ?. Predicates are often built from other predicates.

(define (cold? t) (< t 8))
(define (cool? t) (and (< t 16) (not (cold? t))))
(define (hot? t) (> t 30))
(define (warm? t) (not (or (cold? t) (cool? t) (hot? t))))
(check-expect (cool? 12) true)
(check-expect (warm? 20) true)
(check-expect (warm? 32) false)
Shortcut: no cond needed

A predicate body is usually one Bool expression. Don't wrap it in a cond that produces true/false.

;; clunky
(define (teen? age) (cond [(and (>= age 13) (<= age 19)) true]
                          [else false]))
;; better
(define (teen? age) (and (>= age 13) (<= age 19)))

Built-in predicates by the midterm: zero? number? boolean? inexact? symbol? empty? cons? list? even? odd? char? string?.

These rules are the semantics (meaning) of a program. Syntax is only its form: (+ 5 2 is a syntax error; (+ 5 2) ⇒ 7 is semantics.

On the exam

"Show the substitution steps" or "write the next step". Label each step with its rule if asked. The common slips: doing two rewrites in one step, applying a function before its arguments are values, or forgetting that replacing a constant's name is a step.

  • Irrational numbers can't be stored exactly, so Racket uses hardware floating point, shown with a #i prefix: (sqrt 2) ⇒ #i1.4142135623730951. About 16 significant digits; range roughly ±10308.
  • Num means any number: Nat, Int, Rat or inexact. Nat ⊆ Int ⊆ Rat ⊆ Num.
  • Inexact values come from sqrt of non-perfect squares, trig, log, exp, pi, e. (sqrt 4) is still exactly 2.
  • Inexact is contagious: (+ 1 #i0.5) ⇒ #i1.5.
  • number? asks "is this any number" (not a Bool, symbol, list…). inexact? asks "is this number inexact". boolean? asks "is this a Bool".

(sin pi) ⇒ #i1.2246467991473532e-16, so (= (sin pi) 0) is false. Compare with a tolerance instead: (< (abs (- x y)) 0.0001). In tests, check-expect with an inexact result is an error ("cannot be an inexact number"); use check-within.

Conditional expressions

cond, symbols, testing and contracts. After this lecture every function you submit needs a purpose, a contract, the code and full-coverage tests.

You should know

  • Writing question/answer pairs with cond and else
  • The substitution rules for cond, and stepping a conditional
  • Producing and consuming symbols: Sym, symbol?, symbol=?
  • Testing with check-expect and check-within; finding boundary cases from a cond
  • Writing and reading contracts
  • What an assignment submission must include

;; Choose outerwear for a temperature in degrees C.
;; what-to-wear: Num -> (anyof 'jacket 'sweater 'shirt)
(define (what-to-wear t)
  (cond [(< t 8)  'jacket]
        [(< t 16) 'sweater]     ; already know t >= 8 here
        [else     'shirt]))
(check-expect (what-to-wear -34) 'jacket)
(check-expect (what-to-wear 7) 'jacket)
(check-expect (what-to-wear 8) 'sweater)
(check-expect (what-to-wear 15) 'sweater)
(check-expect (what-to-wear 16) 'shirt)
(check-expect (what-to-wear 38) 'shirt)
  • Each [question answer] pair: the question must evaluate to a Bool; the answer can be any value. Square brackets are a readability convention (the stepper may show round ones).
  • Questions are tried top to bottom. The first true question's answer is the value of the whole cond; nothing after it is evaluated.
  • Order matters. Every question can assume all earlier questions were false, so don't repeat their conditions. Above, the second question doesn't need (and (>= t 8) …).
  • else catches everything left and must be last. If no question is true and there is no else: error "all question results were false".
Trap: don't nest else (cond …)

[else (cond [A x] [else y])] should be flattened into the outer cond as [A x] [else y]. Markers and the submission system flag the nested version.

Shortcut: Bool conds collapse
Instead ofWrite
(cond [A true] [else false])A

(cond [A B] [else false])(and A B)

(cond [false e] …)  ⇒  (cond …)     ; drop a false pair
(cond [true e] …)   ⇒  e            ; take the answer, discard the rest
(cond [else e])     ⇒  e
Steps
  1. Evaluate only the first question, one substitution at a time, until it is true or false.
  2. If false: one step deletes that pair. Go back to step 1 with the new first pair.
  3. If true (or the pair is else): one step replaces the whole cond with that answer. Answers are never evaluated before they are chosen.
(define (sign x) (cond [(> x 0) 'pos] [(< x 0) 'neg] [else 'zero]))
(sign 0)
⇒ (cond [(> 0 0) 'pos] [(< 0 0) 'neg] [else 'zero])
⇒ (cond [false 'pos] [(< 0 0) 'neg] [else 'zero])
⇒ (cond [(< 0 0) 'neg] [else 'zero])
⇒ (cond [false 'neg] [else 'zero])
⇒ (cond [else 'zero])
⇒ 'zero
Trap

Dropping a false pair is its own step, and so is the final (cond [else e]) ⇒ e. Answers stay unevaluated (with the parameter values substituted in) until their pair is chosen.

  • A symbol is a value written with a leading quote: 'jacket, 'CS135. It means something to you, not to Racket. Symbols are self-documenting labels, so you don't need constants like (define jacket 0).
  • No arithmetic on symbols; the only thing you do is compare them.
  • (symbol=? a b): both arguments must be symbols. (symbol=? 'blue 42) is an error.
  • (symbol? v): works on any value. (symbol? 42) ⇒ false.
  • Symbols are case-sensitive: (symbol=? 'Apple 'apple) ⇒ false.
Trap: mixed data needs a type check first

When a value can be a number or a symbol (like a card Rank: 2–10 or 'jack…), check the type before comparing, or the comparison errors:

;; rank=?: Rank Rank -> Bool
(define (rank=? r0 r1)
  (or (and (symbol? r0) (symbol? r1) (symbol=? r0 r1))
      (and (number? r0) (number? r1) (= r0 r1))))
(check-expect (rank=? 'ace 'ace) true)
(check-expect (rank=? 2 2) true)
(check-expect (rank=? 'king 10) false)

Short-circuiting makes this safe: symbol=? only runs once both are known to be symbols.

  • (check-expect actual-expr expected-value): passes when they are equal. Use it for exact numbers, Bools, symbols, lists, strings.
  • (check-within actual-expr expected-value delta): passes when they differ by at most delta. Use it whenever the result is inexact: (check-within (sqrt 2) 1.414 0.001).
  • Tests can sit anywhere in the file, even above the function; they run after everything is defined.
  • Before coding, write tests ("examples") worked out by hand: they show whether you understand the problem. After coding, add tests until coverage is complete.

Steps: tests from a cond
  1. For each question except else: at least one test where it is true and one where it is false (and the earlier ones are false).
  2. For each threshold, test at the threshold and just on either side. Thresholds 8 and 16 → test 7, 8, 15, 16.
  3. Add extremes: −34, 38, very large, 0.
  4. Run. Any code DrRacket highlights was never executed, so coverage is incomplete. Assignments require zero highlighting.
Shortcut: standard test checklist
  • Nat recursion: 0, 1, a larger n.
  • Lists: empty; one element; target at the front, in the middle, at the end; all match; none match; duplicates.
  • Two lists: both empty, each one empty, different lengths.
  • Sorted input: already sorted, reversed, with equal values.

A contract is a comment saying what types a function consumes and produces: ;; name: In1 In2 -> Out.

  • Types by the midterm: Nat Int Rat Num Bool Sym Char Str Any, (listof X), (anyof …), and names from your data definitions (Point, Card, AL).
  • Use the most precise type that is true. Counting → Nat. Anything with division or sqrt → Num.
  • anyof lists the exact values or types allowed: Num -> (anyof 'jacket 'sweater 'shirt), (anyof Num empty). Num -> Sym is also acceptable unless anyof is requested.
  • Add a Requires line for limits the types can't express:
;; last: (listof Any) -> Any
;; Requires: lst is non-empty
;; insert: Num (listof Num) -> (listof Num)
;; Requires: lst is sorted in ascending order

  1. Purpose: what the function produces, in terms of its parameter names.
  2. Contract (plus Requires if needed).
  3. The function definition.
  4. Tests giving full coverage.

Default grading: purpose 5%, contract 5%, coverage 10%, correctness 80% (share of hidden tests passed). From L08: helper functions you invent don't lose marks for a missing purpose or contract, but still need test coverage.

Recursion on natural numbers

A function defined in terms of itself on a smaller argument. With big numbers, conditionals and recursion, the model is Turing complete: it can compute anything any computer can.

You should know

  • Using the design recipe to write functions
  • Writing recursive functions that follow version 1 of the Rules for Recursion
  • Using zero? and sub1
  • Why those rules guarantee termination
  • Measuring efficiency with the stepper

Steps
  1. Purpose: understand the problem and write it down.
  2. Contract and header: types, then (define (name params) …).
  3. Examples, worked out by hand, as check-expects.
  4. Body, starting from a template.
  5. More tests for boundary cases and coverage.
;; (1) Compute n! (the product 1·2·…·n), with 0! = 1.
;; (2) factorial: Nat -> Nat
(define (factorial n)
  ;; (4) body from the Nat template
  (cond [(zero? n) 1]
        [else (* n (factorial (sub1 n)))]))
;; (3) examples, (5) boundaries
(check-expect (factorial 0) 1)
(check-expect (factorial 1) 1)
(check-expect (factorial 3) 6)
(check-expect (factorial 5) 120)

How to write each step, and the test rules: Design recipe & style.

(define (nat-template n)
  (cond [(zero? n) …]                          ; base case
        [… …]                                  ; optional extra cases
        [else (… n … (nat-template (sub1 n)))]))
Steps: filling the template
  1. Write the maths as a recurrence: f(0) = ?, f(n) = something using f(n−1). For sum-to: f(0) = 0, f(n) = n + f(n−1).
  2. The base answer goes in [(zero? n) …].
  3. Trust that (f (sub1 n)) already gives the right answer for n−1 (the "leap of faith"). Ask only how to turn that into the answer for n.
  4. If some n need different handling (only multiples of 3 count, say), add a middle clause.
;; sum-to: Nat -> Nat        0 + 1 + … + n
(define (sum-to n)
  (cond [(zero? n) 0]
        [else (+ n (sum-to (sub1 n)))]))
(check-expect (sum-to 4) 10)
(check-expect (sum-to 0) 0)

;; power: Num Nat -> Num      b^n by repeated multiplication
(define (power b n)
  (cond [(zero? n) 1]
        [else (* b (power b (sub1 n)))]))   ; b never changes
(check-expect (power 2 10) 1024)
(check-expect (power 5 0) 1)

;; count-mult3: Nat -> Nat    how many of 1..n are divisible by 3
(define (count-mult3 n)
  (cond [(zero? n) 0]
        [(zero? (remainder n 3)) (add1 (count-mult3 (sub1 n)))]
        [else (count-mult3 (sub1 n))]))
(check-expect (count-mult3 10) 3)
(check-expect (count-mult3 2) 0)
Shortcut: picking the base value

It is the answer for 0, which is usually the identity of the combining operation: 0 for +, 1 for *, empty when building a list with cons, true for "all", false for "any".

  • (zero? n) is true only when n is 0. It is the termination test for Nat recursion.
  • (sub1 n) is n − 1. It is the only allowed way to make a Nat argument smaller. (add1 arrives in L06.)

Rules, version 1
  1. Change one argument closer to termination when recurring. No other argument may change.
  2. When recurring on a natural number, use (sub1 n) and test termination with zero?.

Why it terminates: n is a Nat, and each recursive call is on n − 1. A Nat can only be decreased by 1 a finite number of times before it reaches 0, where zero? stops the recursion.

The three properties CS135 cares about: termination (guaranteed by the rules), correctness (could be proved by induction; we use tests), efficiency (count of substitution steps).

Trap
  • Called with −1 or 2.5, the function never reaches 0 and runs forever. That is why the contract says Nat.
  • Not allowed: recursing on (- n 2), (quotient n 10) or (add1 n), or testing termination with (= n 1) or (<= n 0) instead of zero?.
  • "No other argument may change": power above passes b through unchanged. In v1 only one argument may move. (L09 allows several; L10 allows accumulators.)

  • Efficiency in CS135 = number of substitution steps. DrRacket's Stepper shows a counter like 1/64: (sum-to 10) takes 64 steps.
  • The counter counts every expression the stepper shows, the starting one included, so it is one more than the number of ⇒ arrows.
  • (sum-to n) takes 6n + 4: four steps for the base case, six per level of recursion (expand the call, evaluate the question, drop the false pair, take else, sub1, and the final +).

  • Two kinds of scope for now: global (top-level definitions) and function (parameters, visible only inside that body).

Recursion on a list

A list is defined recursively, so functions on lists are recursive in the same shape. This lecture is about folding a list down to one value, and predicates over lists.

You should know

  • Writing recursive functions that fold lists, using the design recipe, the template and the Rules for Recursion (v2)
  • Writing predicates over lists the same way
  • You can't use member? or equal?

;; A (listof X) is one of:
;; * empty
;; * (cons X (listof X))

(define (listof-X-template lox)
  (cond [(empty? lox) …]
        [… …]                                     ; optional cases on (first lox)
        [else (… (first lox) … (listof-X-template (rest lox)) …)]))

Replace X with a real type (Num, Sym, Point), or use Any when the function doesn't care what the elements are.

Steps: the four questions
  1. What should the function produce for the empty list (the base case)?
  2. What should it do with the first element of a non-empty list?
  3. What does the recursive call on the rest produce? (Assume it's correct.)
  4. How do I combine 2 and 3 into the answer for the whole list?
Rules for Recursion, version 2
  1. Change one argument closer to termination; no other argument may change.
  2. On a natural number: (sub1 n), test with zero?.
  3. On a list: (rest lst), test with empty?.

The empty case always comes first in the cond, so first/rest are never applied to empty. Extra parameters that don't drive the recursion (like a target symbol) are passed along unchanged.

Trap

Recursing in a question of a cond is almost always a mistake (and leads to the exponential blow-up in L08). Recursing in two different answers is fine, because only one answer runs.

Folding (or reducing) boils a whole list down to one value: a count, a sum, a length, a Bool. You pick a base value for empty and a way to combine each element with the answer for the rest.

Producing a list

The other two list idioms, filter and map, plus ordered lists and functions on non-empty lists.

You should know

A filter produces the sublist of elements that pass a test, in the original order. The whole trick: to delete an element, don't cons it; just return the recursive result. To keep it, cons it onto the recursive result.

;; Remove every occurrence of target.
;; eat-symbol: Sym (listof Sym) -> (listof Sym)
(define (eat-symbol target los)
  (cond [(empty? los) empty]
        [(symbol=? target (first los))
         (eat-symbol target (rest los))]                    ; drop: no cons
        [else (cons (first los) (eat-symbol target (rest los)))]))  ; keep
(check-expect (eat-symbol 'apple (cons 'apple (cons 'eggs (cons 'apple empty))))
              (cons 'eggs empty))
(check-expect (eat-symbol 'apple empty) empty)

;; Keep only even numbers.
;; keep-even: (listof Int) -> (listof Int)
(define (keep-even loi)
  (cond [(empty? loi) empty]
        [(odd? (first loi)) (keep-even (rest loi))]
        [else (cons (first loi) (keep-even (rest loi)))]))
(check-expect (keep-even (cons 4 (cons -3 (cons -8 (cons 1 empty)))))
              (cons 4 (cons -8 empty)))

Variation: remove only the first occurrence

;; remove-first: Sym (listof Sym) -> (listof Sym)
(define (remove-first target los)
  (cond [(empty? los) empty]
        [(symbol=? target (first los)) (rest los)]   ; found: stop, keep the rest as is
        [else (cons (first los) (remove-first target (rest los)))]))
(check-expect (remove-first 'a (cons 'b (cons 'a (cons 'a empty))))
              (cons 'b (cons 'a empty)))
Shortcut

eat-symbol (remove all) recurses after a match; remove-first produces (rest los) and stops. The same "stop early" move appears in insert and in dictionary delete (L12).

Trap

Forgetting (cons (first lst) …) in the keep branch silently deletes everything. Consing in the drop branch deletes nothing. Base case for a list-producing function is empty, not 0.

A map produces a list of the same length, with a transformation applied to every element. Every non-empty branch conses something.

;; add1-list: (listof Num) -> (listof Num)
(define (add1-list lon)
  (cond [(empty? lon) empty]
        [else (cons (add1 (first lon)) (add1-list (rest lon)))]))
(check-expect (add1-list (cons 10 (cons -6 empty))) (cons 11 (cons -5 empty)))
(check-expect (add1-list empty) empty)

;; A conditional map: replace one symbol with another.
;; replace: Sym Sym (listof Sym) -> (listof Sym)
(define (replace old new los)
  (cond [(empty? los) empty]
        [(symbol=? old (first los)) (cons new (replace old new (rest los)))]
        [else (cons (first los) (replace old new (rest los)))]))
(check-expect (replace 'apple 'orange (cons 'apple (cons 'milk empty)))

;; scale: Num (listof Num) -> (listof Num)

        [else (cons (* k (first lon)) (scale k (rest lon)))]))

  • Shorter-or-equal list, same elements → filter.
  • Same-length list, changed elements → map.

A property about neighbours needs two elements at a time, so there are two base cases: an empty list and a one-element list are both trivially ordered.

;; ascending?: (listof Num) -> Bool
(define (ascending? lon)
  (cond [(or (empty? lon) (empty? (rest lon))) true]
        [(> (first lon) (first (rest lon))) false]   ; neighbours out of order
        [else (ascending? (rest lon))]))              ; (rest lon), NOT (rest (rest lon))
(check-expect (ascending? empty) true)
(check-expect (ascending? (cons -10 empty)) true)
(check-expect (ascending? (cons 10 (cons 20 (cons 30 empty)))) true)
(check-expect (ascending? (cons 1 (cons 1 empty))) true)
(check-expect (ascending? (cons 3 (cons 1 (cons 2 empty)))) false)

Trap

;; Insert n into its place in a sorted list.
;; insert: Num (listof Num) -> (listof Num)
;; Requires: lon is sorted in ascending order
(define (insert n lon)
  (cond [(empty? lon) (cons n empty)]                  ; end of list: n goes last
        [(< n (first lon)) (cons n lon)]                ; found its spot: stop
        [else (cons (first lon) (insert n (rest lon)))])) ; keep looking
(check-expect (insert -1 empty) (cons -1 empty))
(check-expect (insert 0 (cons 1 (cons 2 empty))) (cons 0 (cons 1 (cons 2 empty))))
(check-expect (insert 3 (cons 1 (cons 2 (cons 4 empty)))) (cons 1 (cons 2 (cons 3 (cons 4 empty)))))
(check-expect (insert 5 (cons 1 (cons 2 empty))) (cons 1 (cons 2 (cons 5 empty))))
(check-expect (insert 2 (cons 1 (cons 2 empty))) (cons 1 (cons 2 (cons 2 empty))))
The three cases
  1. Empty list: the result is the one-element list (cons n empty), not empty.
  2. n belongs before the first element: (cons n lon). The rest is already sorted, so stop recursing.
  3. Otherwise keep the first element and insert into the rest.
Trap

Losing (first lon) in case 3, returning empty in case 1, or recursing again after inserting (duplicating n). Test front, middle, end, empty, and a duplicate value.

  • (second lst) = (first (rest lst)), needs length ≥ 2. (third lst) = (first (rest (rest lst))), needs length ≥ 3. Too short is an error.
  • fourth through eighth exist but are not allowed. Needing them means there's a simpler approach (probably recursion).
  • Great for fixed-size data: (define (get-y p) (second p)).

Trap

Run the function on lists of length 0, 1, 2, 3, … and record the step counts. Then fit a formula:

Steps: from a table of step counts to a formula
  1. Take differences between consecutive counts. Constant first differences d → linear: f(n) = d·n + f(0).
  2. If the first differences grow by a constant amount s (constant second differences) → quadratic: a = s/2, c = f(0), b = f(1) − a − c.
  3. If each count is roughly double the previous → exponential.

Recursive idea: sort the rest of the list, then insert the first element into its place. It reuses insert from L07 as a helper.

;; sort: (listof Num) -> (listof Num)
(define (sort lon)
  (cond [(empty? lon) empty]
        [else (insert (first lon) (sort (rest lon)))]))
(check-expect (sort empty) empty)

(check-expect (sort (list 5 -10 1 14 3 1 8)) (list -10 1 1 3 5 8 14))
(check-expect (sort (list 3 2 1)) (list 1 2 3))

It follows the Rules (one recursive call on (rest lon)), but it's quadratic: n recursive calls, and each insert may walk the whole sorted rest. Already-sorted input is fastest (each insert stops immediately); reversed input is the worst case.

Trap: hidden quadratic

Calling length, append, reverse or your own list-walking helper inside every recursive step turns a linear function quadratic. Sometimes that's fine (it's not exponential), but reverse inside a recursive function is a red flag.

Practical rule from the slides: if your code handles a list of a few hundred elements in under ten seconds, it's efficient enough. Only exponential blow-up is a real problem.

;; BAD: (largest-slow (rest lst)) can be evaluated twice
(define (largest-slow lst)
  (cond [(empty? (rest lst)) (first lst)]
        [(> (first lst) (largest-slow (rest lst))) (first lst)]   ; call #1, in a question
        [else (largest-slow (rest lst))]))                       ; call #2

When the first element isn't the biggest, both calls run on the same rest, and each of those makes two calls, and so on: up to 2ⁿ − 1 calls. On ascending input of length 25 it practically never finishes.

Steps: the fix
  1. Spot the smell: the same recursive call written twice (often once in a question and once in an answer).
  2. Make the recursive call once and hand its result to a helper (or a built-in like max) as an argument. Inside the helper it's a plain value, so using it twice is free.
;; larger: Num Num -> Num
(define (larger a b)
  (cond [(> a b) a]
        [else b]))
;; largest: (listof Num) -> Num
;; Requires: lon is non-empty
(define (largest lon)
  (cond [(empty? (rest lon)) (first lon)]
        [else (larger (first lon) (largest (rest lon)))]))   ; one call: linear

(check-expect (largest (list 9 -2 4)) 9)
;; equivalently: (max (first lon) (largest (rest lon)))
Trap

Two recursive calls in different answers of a cond are fine: only one answer ever runs. The problem is two calls on the same input within one evaluation.

;; Produce the item at position n (counting from 0), or empty if there is none.
;; index: Nat (listof Any) -> Any
(define (index n lst)
  (cond [(empty? lst) empty]          ; ran out of list: check this FIRST
        [(zero? n) (first lst)]       ; safe: lst is non-empty here

;; first-n: Nat (listof Any) -> (listof Any)
(define (first-n n lst)

Returning empty for "no such item" makes the contract (anyof X empty). The same "failure value" idea returns in dictionary lookup (L12).

Rules for Recursion, final version
  1. Change at least one argument closer to termination while recurring. Arguments not involved in recursion should not change.
  2. When recurring on a natural number, use (sub1 n) and test termination with zero?.
  3. When recurring on a list, use (rest lst) and test termination with empty?.

Rules 2 and 3 guarantee termination: every recursive call has some argument that is strictly smaller, and it must eventually hit 0 or empty. L10 adds one exception: accumulators (arguments not involved in termination) may change.

;; appnd: (listof Any) (listof Any) -> (listof Any)
(define (appnd lst0 lst1)
  (cond [(empty? lst0) lst1]                                ; nothing left of lst0
        [else (cons (first lst0) (appnd (rest lst0) lst1))])) ; lst1 never changes

;; merge: (listof Num) (listof Num) -> (listof Num)
;; Requires: both lists sorted in ascending order
(define (merge lst1 lst2)
  (cond [(empty? lst1) lst2]
        [(empty? lst2) lst1]
        [(< (first lst1) (first lst2))
         (cons (first lst1) (merge (rest lst1) lst2))]     ; only lst1 shrinks
        [(> (first lst1) (first lst2))
         (cons (first lst2) (merge lst1 (rest lst2)))]     ; only lst2 shrinks
        [else (cons (first lst1)                           ; equal: take both
                    (cons (first lst2) (merge (rest lst1) (rest lst2))))]))

(check-expect (merge (list 1 2 2 3 3) (list 1 2 3 3)) (list 1 1 2 2 2 3 3 3 3))
(check-expect (merge empty (list 1)) (list 1))

  3. Decide what unequal lengths mean (stop? treat missing as 0? error via Requires?) and write a test for it.

Accumulative recursion

An extra parameter that carries information down the recursion instead of combining results on the way back up. This is the end of the "fundamentals" half of the course.

You should know

  • Accumulators and accumulative recursion
  • Reversing a list with an accumulator
  • Counting up and down with limits
  • How the standard list functions work on lists in lists

An accumulator is a parameter that keeps track of partial results or context as you go down the list. It isn't what makes the recursion stop (the list or Nat still does that), so it is allowed to change on every call. A wrapper function gives it its starting value and hides it from the user.

Steps: writing an accumulator function
  1. Decide what you need to remember about the part of the list you've already passed: the answer so far, a running total, the current position, the previous element, the largest so far.
  2. Add that parameter to a helper (name it like fn/acc) and pick its starting value: empty for a list, 0 for a sum or position, 1 for a product, the first element for a max.
  3. In the recursive call, recur on (rest lst) and pass an updated accumulator.
  4. In the base case, usually produce the accumulator (or something built from it).
  5. Write the wrapper with the original contract: (define (fn lst) (fn/acc lst start)).

Two styles to recognise:

  • The accumulator holds the answer (reverse, sum): the base case returns it.
  • The accumulator holds context (position, running total, previous item): you still build the answer with cons in the normal way, and the base case returns empty.
;; Style 1: the accumulator IS the answer so far.
;; sum/acc: (listof Num) Num -> Num
(define (sum/acc lon total)
  (cond [(empty? lon) total]
        [else (sum/acc (rest lon) (+ total (first lon)))]))
;; sum-all: (listof Num) -> Num
(define (sum-all lon) (sum/acc lon 0))
(check-expect (sum-all (list 1 2 3 4)) 10)
(check-expect (sum-all empty) 0)

;; Style 2: the accumulator is context (a running total); output built by cons.
;; running/acc: (listof Num) Num -> (listof Num)
(define (running/acc lon total)
  (cond [(empty? lon) empty]
        [else (cons (+ total (first lon))
                    (running/acc (rest lon) (+ total (first lon))))]))
;; running-sums: (listof Num) -> (listof Num)
(define (running-sums lon) (running/acc lon 0))
(check-expect (running-sums (list 1 2 3 4)) (list 1 3 6 10))

;; Style 2 again: the accumulator is the current position.
;; positions/acc: Sym (listof Sym) Nat -> (listof Nat)
(define (positions/acc target los pos)
  (cond [(empty? los) empty]
        [(symbol=? target (first los))
         (cons pos (positions/acc target (rest los) (add1 pos)))]
        [else (positions/acc target (rest los) (add1 pos))]))
;; positions-of: Sym (listof Sym) -> (listof Nat)
(define (positions-of target los) (positions/acc target los 0))
(check-expect (positions-of 'a (list 'a 'b 'a 'c)) (list 0 2))
Trap
  • Building a list by consing onto an accumulator produces it reversed. If you need the original order, use plain recursion, or reverse once in the wrapper.
  • Wrong starting value in the wrapper (0 for a product, for example).
  • Don't reach for an accumulator for a plain fold, map or filter. Use one when you need information about elements you've already passed.

Move elements one at a time from the front of the list onto the front of the accumulator. The accumulator ends up reversed.

;; rev/acc: (listof Any) (listof Any) -> (listof Any)
(define (rev/acc lst acc)
  (cond [(empty? lst) acc]
        [else (rev/acc (rest lst) (cons (first lst) acc))]))
;; rev: (listof Any) -> (listof Any)
(define (rev lst) (rev/acc lst empty))
(check-expect (rev (list 1 2 3 4 5)) (list 5 4 3 2 1))
(check-expect (rev empty) empty)
(rev/acc (list 1 2 3) empty)
→ (rev/acc (list 2 3) (list 1))
→ (rev/acc (list 3)   (list 2 1))
→ (rev/acc empty      (list 3 2 1))
→ (list 3 2 1)
  • Linear: 7n + 5 steps, versus 3.5n² + 6.5n + 4 for rev-slow with attach.
  • Built-in reverse is allowed from L10 (treat it as linear). Use it once in a wrapper if an answer comes out backwards; never call it inside every recursive step.

Counting down is natural with sub1. Counting up while still following the Rules needs one of three tricks: arithmetic with a limit, an accumulator that counts up, or reversing.

;; count-down: Nat -> (listof Nat)      n, n-1, ..., 0   (n+1 items)
(define (count-down n)
  (cond [(zero? n) (list 0)]
        [else (cons n (count-down (sub1 n)))]))
(check-expect (count-down 3) (list 3 2 1 0))

;; Trick 1, arithmetic: produce limit-n, ..., limit-1.
;; count-up-to: Nat Nat -> (listof Nat)
(define (count-up-to limit n)
  (cond [(zero? n) empty]
        [else (cons (- limit n) (count-up-to limit (sub1 n)))]))
(check-expect (count-up-to 105 5) (list 100 101 102 103 104))

;; Trick 2, accumulator: from counts up while n counts down.
;; count-up-from: Nat Nat -> (listof Nat)    n values starting at from
(define (count-up-from from n)
  (cond [(zero? n) empty]
        [else (cons from (count-up-from (add1 from) (sub1 n)))]))
(check-expect (count-up-from 100 5) (list 100 101 102 103 104))

;; count-up: Nat -> (listof Nat)          0, 1, ..., n-1   (n items)
(define (count-up n) (count-up-from 0 n))
(check-expect (count-up 4) (list 0 1 2 3))
(check-expect (count-up 0) empty)

;; Inclusive range a..b, then map the values if needed.
;; range-incl: Nat Nat -> (listof Nat)
;; Requires: a <= b
(define (range-incl a b) (count-up-from a (add1 (- b a))))
(check-expect (range-incl 3 6) (list 3 4 5 6))
(check-expect (add1-list (count-up 3)) (list 1 2 3))
Trap: off by one

Compare base cases. count-down returns (list 0), so it includes 0 and has n+1 items. countdown from L08 returns empty, so it stops at 1. count-up n stops at n−1. Always check with n = 0 and n = 1.

Steps: evaluating a nested first/rest chain
  1. Start from the innermost call on the named list and write down what it produces.
  2. Apply the next function outward to that value. (rest colours) → list of the last two colours; (first …) → (list 'ember (list 218 82 48)); (rest …) → (list (list 218 82 48)); (first …) → (list 218 82 48); (first …) → 218.
  3. Keep track of "list of X" vs "an X" at every stage. That is where the mistakes happen.

;; d: Point Point -> Num      distance between two points (Point is (list Num Num))
(define (d p0 p1)
  (sqrt (+ (sqr (- (second p1) (second p0)))
           (sqr (- (first p1) (first p0))))))
(check-within (d (list 1 5) (list 4 1)) 5 0.00001)

;; Sum the segments between consecutive points (does NOT close the shape).
;; add-segments: (listof Point) -> Num
(define (add-segments lop)
  (cond [(or (empty? lop) (empty? (rest lop))) 0]       ; adjacent-pair pattern
        [else (+ (d (first lop) (second lop)) (add-segments (rest lop)))]))

;; Version 1: open path + closing segment (walks the list twice).
;; perimeter: (listof Point) -> Num
(define (perimeter poly)
  (+ (d (first poly) (last poly)) (add-segments poly)))

;; Version 2: carry the first point along so the last segment can close the loop.
;; add-segments/wrap: Point (listof Point) -> Num
(define (add-segments/wrap p0 lop)
  (cond [(empty? lop) 0]
        [(empty? (rest lop)) (d p0 (first lop))]        ; last point back to the start
        [else (+ (d (first lop) (second lop)) (add-segments/wrap p0 (rest lop)))]))
;; perimeter/v2: (listof Point) -> Num
(define (perimeter/v2 poly) (add-segments/wrap (first poly) poly))

(define square4 (list (list 1 1) (list -1 1) (list -1 -1) (list 1 -1)))
(check-within (add-segments square4) 6 0.00001)
(check-within (perimeter square4) 8 0.00001)
(check-within (perimeter/v2 square4) 8 0.00001)

A table is a (listof (listof X)): a list of rows. The outer function recurses over rows and hands each row to a helper that recurses over that row's elements.

;; sum-row: (listof Num) -> Num
(define (sum-row row)
  (cond [(empty? row) 0]
        [else (+ (first row) (sum-row (rest row)))]))
;; sum-table: (listof (listof Num)) -> Num          fold over rows
(define (sum-table t)
  (cond [(empty? t) 0]
        [else (+ (sum-row (first t)) (sum-table (rest t)))]))
;; row-sums: (listof (listof Num)) -> (listof Num)  map over rows
(define (row-sums t)
  (cond [(empty? t) empty]
        [else (cons (sum-row (first t)) (row-sums (rest t)))]))
;; flatten: (listof (listof Any)) -> (listof Any)
(define (flatten t)
  (cond [(empty? t) empty]
        [else (append (first t) (flatten (rest t)))]))
(define tbl (list (list 1 2 3) (list 4 5) empty))
(check-expect (sum-table tbl) 15)
(check-expect (row-sums tbl) (list 6 9 0))
(check-expect (flatten tbl) (list 1 2 3 4 5))

(define (times/row n m i)

;; A Set is a (listof Sym) with no duplicates.
;; For each subset produce two: one with sym, one without. Plus (list sym) alone.
;; expand: Sym (listof Set) -> (listof Set)
(define (expand sym subs)
  (cond [(empty? subs) (list (list sym))]
        [else (cons (cons sym (first subs))
                    (cons (first subs) (expand sym (rest subs))))]))
;; All non-empty subsets.
;; subsets: Set -> (listof Set)
(define (subsets s)
  (cond [(empty? s) empty]
        [else (expand (first s) (subsets (rest s)))]))
(check-expect (subsets (list 'a 'b 'c))
              (list (list 'a 'b 'c) (list 'b 'c) (list 'a 'c) (list 'c)
                    (list 'a 'b) (list 'b) (list 'a)))
(check-expect (subsets empty) empty)
  • A set of n symbols has 2ⁿ − 1 non-empty subsets, so the output itself grows exponentially. That's the size of the answer, not a blow-up bug: subsets makes one recursive call.
  • Same shape as insertion sort: f(lst) = helper(first, f(rest)), where the helper walks the result of the recursion.

  • Computers store everything as numbers. To exchange text, everyone must agree which number means which character.
  • Unicode assigns a unique number, a code point, to almost every character in almost every written language. Written in base 16 with a U+ prefix: U+0061 = 97 = "a".

  • "a" and "A" are different characters. For CS135, two characters are the same exactly when their code points are the same.

Steps: the string pattern
  1. Wrapper (contract uses Str): convert each string with string->list.
  2. Helper (contract uses (listof Char)): an ordinary list function: fold, filter, map, lockstep.

;; Fold: count occurrences of a character.
;; count-char/list: Char (listof Char) -> Nat
(define (count-char/list c loc)
  (cond [(empty? loc) 0]
        [(char=? c (first loc)) (add1 (count-char/list c (rest loc)))]
        [else (count-char/list c (rest loc))]))
;; count-char: Char Str -> Nat
(define (count-char c s) (count-char/list c (string->list s)))
(check-expect (count-char #\l "hello world") 3)

;; no-spaces/list: (listof Char) -> (listof Char)
(define (no-spaces/list loc)

        [(char=? #\space (first loc)) (no-spaces/list (rest loc))]
        [else (cons (first loc) (no-spaces/list (rest loc)))]))

(define (no-spaces s) (list->string (no-spaces/list (string->list s))))
(check-expect (no-spaces "a b  c") "abc")

;; Lockstep: string equality written by hand.
;; char-list=?: (listof Char) (listof Char) -> Bool
(define (char-list=? loc0 loc1)
  (cond [(empty? loc0) (empty? loc1)]      ; equal only if both ran out together
        [(empty? loc1) false]
        [else (and (char=? (first loc0) (first loc1))
                   (char-list=? (rest loc0) (rest loc1)))]))
;; str=?: Str Str -> Bool
(define (str=? s0 s1) (char-list=? (string->list s0) (string->list s1)))
(check-expect (str=? "hello" "hello") true)
(check-expect (str=? "hello" "help") false)
(check-expect (str=? "" "") true)
(check-expect (str=? "ab" "abc") false)

  1. Compare character by character from the left.
  2. At the first position where they differ, the smaller code point comes first.
  3. If one string runs out first (it's a prefix of the other), the shorter one comes first. "" comes before every non-empty string.
;; char-list<?: (listof Char) (listof Char) -> Bool
(define (char-list<? loc0 loc1)
  (cond [(empty? loc0) (not (empty? loc1))]     ; prefix (or equal) case
        [(empty? loc1) false]
        [(char=? (first loc0) (first loc1)) (char-list<? (rest loc0) (rest loc1))]
        [else (char<? (first loc0) (first loc1))]))   ; first difference decides
;; str<?: Str Str -> Bool
(define (str<? s0 s1) (char-list<? (string->list s0) (string->list s1)))
(check-expect (str<? "planet" "plants") true)
(check-expect (str<? "plan" "plants") true)
(check-expect (str<? "" "a") true)
(check-expect (str<? "abc" "abc") false)
(check-expect (str<? "Zebra" "apple") true)
(check-expect (string<? "10" "9") true)
Trap

Lexicographic is not numeric: "10" < "9" because #\1 < #\9. And capitals sort before every lowercase letter.

  • A dictionary stores key-value pairs. Keys are unique; values may repeat (two students can have the same mark).
  • Operations: lookup (also find/search): key → its value; add (insert): store a pair; delete (remove): drop a key and its value.
  • It's an abstract data type: it says what the operations do, not how they're stored. An association list is one implementation.
  • Examples: word → definition, name → phone number, user ID → seat, stock symbol → price.

;; An association list (AL) is a (listof (list Str Num))
;; Requires: each key (Str) is unique
(define marks (list (list "asmith" 87) (list "bjones" 64) (list "cwang" 87)))

;; lookup: Str AL -> (anyof Num empty)
(define (lookup key al)
  (cond [(empty? al) empty]                                   ; not found
        [(string=? key (first (first al))) (second (first al))] ; key of 1st pair matches
        [else (lookup key (rest al))]))
(check-expect (lookup "bjones" marks) 64)
(check-expect (lookup "nobody" marks) empty)

;; delete: Str AL -> AL
(define (delete key al)
  (cond [(empty? al) empty]
        [(string=? key (first (first al))) (rest al)]          ; keys unique: stop here
        [else (cons (first al) (delete key (rest al)))]))
(check-expect (delete "bjones" marks) (list (list "asmith" 87) (list "cwang" 87)))
(check-expect (delete "x" empty) empty)

;; add: Str Num AL -> AL       new or replaced pair goes on the FRONT
(define (add key value al) (cons (list key value) (delete key al)))
(check-expect (add "dlee" 48 marks)
              (list (list "dlee" 48) (list "asmith" 87) (list "bjones" 64) (list "cwang" 87)))
(check-expect (add "cwang" 100 marks)
              (list (list "cwang" 100) (list "asmith" 87) (list "bjones" 64)))
  • Why empty for a failed lookup? Any number could be a real value, so failure must be something that can't be confused with one. Contract: (anyof Num empty).
  • Why delete stops at the first match: keys are unique, so there's nothing left to remove. Return (rest al).
  • Why add deletes first: to keep keys unique when the key already exists. This makes add double as "update".
Trap
  • The key is (first (first al)) and the value is (second (first al)). Returning (first al) returns the whole pair.
  • Use the equality for the key type: string=? for Str, symbol=? for Sym, = for Num.
  • add puts the pair at the front; expected lists in check-expect must match that order exactly.

Shortcut: the order you write in isn't the order on the page

You write purpose → contract and header → examples → body → extra tests. On the page the examples just sit with the other tests below the definition, as the slides show. Racket runs every test after all the definitions, so where a test sits doesn't change whether it runs.

The purpose says what the function does: what it produces and what it consumes, wherever the contract alone doesn't make that clear. It is graded on its own (5% by default).

Steps
  1. Start with a verb that names the output: Compute, Count, Produce, Determine if, Insert, Filter, Convert. For a predicate, a yes/no question works too: ;; Are two strings equal?
  2. Name the inputs, using parameter names where that's clearer: ;; Count how many times sym appears in lst.
  3. Add anything the types can't say: "of a non-empty list", "into lon, which is sorted", "produce empty if i is out of range".
  4. Keep it to one or two lines. Say what comes out, not how: never "uses recursion to …".

Requires

Requires is for limits the types can't express. Callers promise to respect it, so you don't handle or test inputs that break it.

Trap: contract mistakes that cost marks
  • An average or any division with -> Nat: (/ 7 2) is 7/2, so it's -> Num.

Shortcut

Once the template is chosen, the Pattern library usually has the filled-in shape for the question's wording.

(check-expect  (function-call …)  expected-value)
(check-within  (function-call …)  expected-value  delta)
  • The call you're testing goes first, the answer second.
  • The expected value is a plain value you worked out by hand: 6, true, 'jacket, (list 1 2 3), empty, "abc", #\a. Never compute it by calling your own function or copying its code: that test passes even when the function is wrong.
  • Use check-within whenever the result is inexact: sqrt of a non-square, sin, pi, anything shown with #i. In our language, check-expect on an inexact result is an error. The question usually gives the delta.
  • Exact fractions and decimals are fine in check-expect: decimals like 3.5 are exact in our language.
  • With list abbreviations, write expected lists with list. (list 1 2) and (cons 1 (cons 2 empty)) are the same value.
;; Exact results: check-expect, even for fractions and decimals.
(check-expect (/ 7 2) 7/2)
(check-expect (/ 7 2) 3.5)

;; Long tests: put the call and the expected value on separate lines.
(check-expect
 (insert 3 (list 1 2 4 5))
 (list 1 2 3 4 5))

;; Big inputs: name them once and reuse them (L07 does this).
(define class-marks (list 88 49 50 73 12 100 51))
(check-expect (count-passing class-marks) 5)

;; Inexact results: check-within, with the delta the question gives.
(check-within (hypotenuse 1 2) 2.23607 0.00001)

The minimum for assignments is full coverage: after running, no code is highlighted. In the slides' words, it's hard to test too much. Coverage is 10% of the marks by default, and hidden tests decide the other 80%, so your own tests are how you find bugs first.

Steps: build the test list
  1. Turn every example in the question into a check-expect first.
  2. Test the base case: the smallest legal input (0, empty, "", or a one-element list if the function requires non-empty).
  3. For each cond question except else: one test where it's true and one where it's false (with the earlier questions false).
  4. For each threshold, test at it and just on each side. Thresholds 8 and 16 → 7, 8, 15, 16.
  5. For a search, put the answer at the front, in the middle and at the end, and once not there at all.
  6. Give every helper and wrapper its own tests. Test an accumulator helper with an accumulator that isn't the starting value.
  7. Run in DrRacket. Highlighted code never ran: add a test that reaches it.

Helpers and wrappers

;; Compute the sum of the numbers in lon.
;; total: (listof Num) -> Num
(define (total lon) (total/acc lon 0))

;; Add the numbers in lon to sum-so-far.
;; total/acc: (listof Num) Num -> Num
(define (total/acc lon sum-so-far)
  (cond [(empty? lon) sum-so-far]
        [else (total/acc (rest lon) (+ (first lon) sum-so-far))]))

(check-expect (total empty) 0)
(check-expect (total (list 1 2 3)) 6)
(check-expect (total/acc empty 5) 5)          ; helper tested on its own,
(check-expect (total/acc (list 1 2) 10) 13)   ; with a non-zero accumulator
  • Helpers you invent: from L08 on, a missing purpose or contract doesn't cost marks, but the code still needs full coverage. Write both anyway: it takes seconds, and the contract catches type mistakes.
  • A helper the question names gets the full recipe.
  • Accumulator helpers: name them fn/acc (the slides use rev/accumulate). The purpose says what the accumulator holds, and the contract includes its type.
  • The wrapper has the contract the question asked for. It only calls the helper with the starting accumulator.
  • Functions can call helpers defined above or below them. Keep each helper next to the function that uses it.

  • Comments: ;; for a whole line, a single ; after code on the same line.
  • Line length: at most 102 characters, DrRacket's default.
  • Brackets: square around each cond pair, round everywhere else.
  • One cond pair per line. If an answer is long, put it on the next line, indented under its question (like count-passing above).
  • Closing parentheses stack at the end of the last line, not on lines of their own (the usual Racket style).
  • Let DrRacket indent: Racket → Reindent All (Cmd-I on a Mac, Ctrl-I on Windows) fixes the indentation of the whole file.
  • Function names: lowercase words joined by hyphens (count-apples). Predicates end in ?. Constructors start with mk- and accessors with get-. The slides prefer a long, clear name like distance-to-origin to a cryptic one like d0.
  • Parameter names: lst, lon (list of numbers), los (symbols), loc (characters), n, sym. Never list, which hides the built-in.
  • No built-in names for your own functions (length, append, remove-all …). Racket refuses with "this name was defined in the language", and then nothing in the file runs.
  • Constants instead of bare numbers: (define cold 8), as in the L03 submission example.
  • Commenting out: Racket → Comment Out with Semicolons, or #| … |#. Never Comment Out with a Box: it can't be marked.

Recipe traps

Contract and header disagree

Three parameters but two types, or the types are in a different order from the parameters.

Purpose says how, not what

"Recurses through the list" earns nothing. Say what is produced, from which inputs.

Missing Requires

The function breaks on empty or on unsorted input, and the contract doesn't say so.

Only "normal" tests

The base case or the else branch is never tested, so the code stays highlighted.

Expected value from your own code

The expected side calls the function being tested, so the test always passes.

check-expect on an inexact result

That's an error, not a failed test. Use check-within.

Testing outside the contract

(factorial -1) or (last empty): behaviour there is undefined, so don't write the test.

Untested helper

Helpers can skip the purpose and contract, but not coverage.

Redefining a built-in

A function named length or remove-all stops the whole file from running.

Pattern library

Exam questions are mostly the same two dozen shapes in new clothes. Match the wording of the question to a shape, then fill in the blanks. … marks the problem-specific parts.

Folding: one value out

Count the elements that …

"How many …", "count the …". Base 0; add1 on a match, plain recursion otherwise.

(cond [(empty? lst) 0]
      [(matches? (first lst)) (add1 (f (rest lst)))]
      [else (f (rest lst))])

Sum / product / total of …

Base is the identity: 0 for +, 1 for *. To total only some elements, add a clause that skips the others.

(cond [(empty? lst) 0]
      [else (+ (value-of (first lst)) (f (rest lst)))])

Is every element …? / Is any element …?

"All", "every", "only" → base true, stop with false. "Any", "some", "contains", "exists" → base false, stop with true.

;; all                                   ;; any
(cond [(empty? lst) true]                (cond [(empty? lst) false]
      [(fails? (first lst)) false]             [(passes? (first lst)) true]
      [else (f (rest lst))])                   [else (f (rest lst))])

Largest / smallest / last (needs a non-empty list)

No sensible answer for empty → base on (empty? (rest lst)), add "Requires: non-empty". Call the recursion once.

(cond [(empty? (rest lst)) (first lst)]
      [else (max (first lst) (f (rest lst)))])   ; min for smallest

Producing a list

Remove / keep only / filter out …

Delete an element by not consing it; keep it by consing it onto the recursive result.

(cond [(empty? lst) empty]
      [(drop? (first lst)) (f (rest lst))]
      [else (cons (first lst) (f (rest lst)))])

Remove only the first occurrence / stop after the first match

On the match, produce (rest lst) and stop. Also the shape of insert and dictionary delete.

(cond [(empty? lst) empty]
      [(target? (first lst)) (rest lst)]
      [else (cons (first lst) (f (rest lst)))])

Transform / convert / add … to each element

Same length out. Every non-empty branch conses something, possibly something different per branch (replace).

(cond [(empty? lst) empty]
      [(special? (first lst)) (cons replacement (f (rest lst)))]
      [else (cons (transform (first lst)) (f (rest lst)))])

Remove duplicates

Filter with a membership helper: drop (first lst) if it appears again in (rest lst). Keeps the last copy of each value. Quadratic, which is fine.

;; num-member?: Num (listof Num) -> Bool
(define (num-member? x lon)
  (cond [(empty? lon) false]
        [(= x (first lon)) true]
        [else (num-member? x (rest lon))]))
;; dedup: (listof Num) -> (listof Num)
(define (dedup lon)
  (cond [(empty? lon) empty]
        [(num-member? (first lon) (rest lon)) (dedup (rest lon))]
        [else (cons (first lon) (dedup (rest lon)))]))
(check-expect (dedup (list 1 2 1 3 2)) (list 1 3 2))

Build a list from a number (countdown, range, n copies)

Recurse on the Nat; base empty (or (list 0) to include 0). Increasing order needs an accumulator counting up (count-up-from).

(cond [(zero? n) empty]
      [else (cons (item-for n) (f (sub1 n)))])

Order and neighbours

Is it sorted? / compare each element to the next

Two base cases; look at (first lst) and (second lst); recur on (rest lst).

(cond [(or (empty? lst) (empty? (rest lst))) …]
      [(bad-pair? (first lst) (second lst)) …]
      [else (f (rest lst))])

Insert in order / sort

insert: empty → one-element list; belongs here → (cons n lst); else keep first and insert into rest. sort = insert first into sorted rest.

Two arguments

Item at position k / first k / drop k

Nat and list move together: (sub1 n) and (rest lst). Check empty? before using first.

(cond [(empty? lst) …]
      [(zero? n) … (first lst) …]
      [else (f (sub1 n) (rest lst))])

Combine two lists element by element

Lockstep: both rest every call. Decide what unequal lengths mean.

(cond [(or (empty? a) (empty? b)) …]
      [else (combine (first a) (first b) (f (rest a) (rest b)))])

Merge two sorted lists / walk two lists at different speeds

Compare the firsts and advance whichever list "wins" (or both on a tie).

Join lists / add to the end

(append lst1 lst2); one element at the end: (append lst (list x)). Writing it yourself: recurse on the first list only.

Accumulators and wrappers

Reverse, or build the answer while walking

Accumulator holds the answer; base returns it; wrapper starts it at empty/0.

(define (f/acc lst acc)
  (cond [(empty? lst) acc]
        [else (f/acc (rest lst) (update acc (first lst)))]))
(define (f lst) (f/acc lst start))

Needs the position, the previous element, or a running total

Accumulator holds context; still build the output with cons; base returns empty.

;; Keep the elements at positions 0, 2, 4, ...   (a Bool flag flips each step)
;; every-other/acc: (listof Any) Bool -> (listof Any)
(define (every-other/acc lst keep?)
  (cond [(empty? lst) empty]
        [keep? (cons (first lst) (every-other/acc (rest lst) (not keep?)))]
        [else (every-other/acc (rest lst) (not keep?))]))
;; every-other: (listof Any) -> (listof Any)
(define (every-other lst) (every-other/acc lst true))
(check-expect (every-other (list 'a 'b 'c 'd 'e)) (list 'a 'c 'e))
(check-expect (every-other empty) empty)
Trap

Recursing on (rest (rest lst)) to skip elements breaks the Rules (only (rest lst) is allowed) and crashes on odd lengths. Use a flag or a position counter instead.

Wrap-around (compare the last with the first)

Pass the original first element along unchanged as an extra parameter (perimeter/v2).

Process a string

Wrapper: string->list; helper on (listof Char); list->string at the end if the answer is a Str.

(define (f s) (list->string (f/list (string->list s))))

Nested data

For each row / sublist …

One function per level. The outer recursion walks the rows and calls a row helper on (first table). A fold over rows, a map over rows, or a filter of rows.

Look up / update by key

Association list: key is (first (first al)), value is (second (first al)). Update = (cons (list key new) (delete key al)).

All combinations / subsets / "for each element, two choices"

Solve the rest recursively, then expand that answer with the first element using a helper.

Steps: choosing the next rewrite
  1. Find the leftmost spot where a rule applies to an expression whose parts are already values.
  2. Apply exactly one rule there. Copy everything else unchanged.
  3. In a cond, only the first question is ever being evaluated. In and/or, evaluate left to right and stop as soon as the rule fires.
Already values (don't step)

Worked trace: a list function

(define (len lst)
  (cond [(empty? lst) 0]
        [else (add1 (len (rest lst)))]))

(len (list 7))
⇒ (cond [(empty? (list 7)) 0] [else (add1 (len (rest (list 7))))])
⇒ (cond [false 0] [else (add1 (len (rest (list 7))))])
⇒ (cond [else (add1 (len (rest (list 7))))])
⇒ (add1 (len (rest (list 7))))
⇒ (add1 (len empty))
⇒ (add1 (cond [(empty? empty) 0] [else (add1 (len (rest empty)))]))
⇒ (add1 (cond [true 0] [else (add1 (len (rest empty)))]))
⇒ (add1 0)
⇒ 1

Worked trace: helpers and short-circuiting

(define (big? n) (> n 10))
(define (check lst) (and (cons? lst) (big? (first lst))))

(check empty)
⇒ (and (cons? empty) (big? (first empty)))
⇒ (and false (big? (first empty)))      ; short-circuit: first is never called
⇒ false

(check (list 12))
⇒ (and (cons? (list 12)) (big? (first (list 12))))
⇒ (and true (big? (first (list 12))))
⇒ (and true (big? 12))
⇒ (and true (> 12 10))
⇒ (and true true)
⇒ true

Counting steps

  • The stepper's counter includes the starting expression, so it is one more than the number of ⇒ arrows in your trace.
  • Built-ins are one step each, including length, append and reverse (but count those as linear when classifying efficiency).
  • Use the language "Beginning Student with List Abbreviations" or your counts won't match the course's.

Traps and common mistakes

The errors that cost marks most often, grouped by where they bite. Read this list the night before.

Syntax and types

Extra parentheses

(5), ((f x)), (empty) all try to call something that isn't a function.

Arity

(+ 5), (* 5), (and true) are errors (need two or more). (- 5) and (max 5) are fine.

The wrong equality

= only for numbers, symbol=? only for symbols, char=? for characters, string=? for strings. Each errors on the wrong type. equal? and member? are banned.

Non-Bool where a Bool is needed

Arguments to and/or/not and every cond question must be true or false.

No else, no match

A cond where every question is false and there's no else errors: "all question results were false".

Define before use, never redefine

Including using one name for a constant and a function. Don't name parameters after built-ins like list.

Subtraction with many arguments

(- 10 1 2) is 7 (10 − 1 − 2), not 11.

Division leaves Nat

(/ 7 2) is 7/2. Averages and ratios are Num, not Nat.

quotient/remainder on non-integers

Error on Rats like 3/2. Sign of remainder follows the first argument.

Inexact numbers and testing

check-expect on an inexact result

Is an error, not just a failure. Any test involving sqrt, trig, pi, log → check-within.

= on inexact values

(= (sin pi) 0) is false. Compare with a tolerance.

Missing coverage

Every cond question needs a test where it's true and one where it's false. Test at each threshold and on both sides.

Bool conds

(cond [A true] [else false]) is just A. Also flatten [else (cond …)].

Lists

first/rest on empty

Always test empty? first in the cond. second/third also need long enough lists.

Element vs list

(first lst) is an element; (rest lst) is a list. Comparing (first lst) to (rest lst) is a type error; you meant (second lst).

cons is not append

(cons (list 1) (list 2)) is (list (list 1) 2). (cons 1 2) errors. To add at the end: (append lst (list x)).

Base case of the wrong type

A function producing a list returns empty at the base, not 0 or false. insert into empty returns (list n), not empty.

Keep/drop swapped

Forgetting (cons (first lst) …) loses elements; consing in the drop branch removes nothing.

Recursing on lst instead of (rest lst)

Infinite recursion. Recursing on (rest (rest lst)) breaks the Rules and skips neighbours.

(list empty) is not empty

It has length 1. length counts only top-level elements.

Missing Requires

Non-empty lists (last, largest) and sorted lists (insert, merge) need a Requires line.

Recursion and efficiency

Same recursive call twice

Especially one in a cond question and one in its answer. Exponential. Call once and pass the result to a helper or max/min.

Linear work in every call

length, append, reverse or a list-walking helper inside each recursive step makes the function quadratic.

Base-case order with two changing arguments

Check every base case, and put the ones that make first unsafe before the ones that use first (index: empty? before zero?).

Illegal recursion

Only (sub1 n) with zero?, and (rest lst) with empty?. Not (- n 2), (quotient n 10), (add1 n) as the shrinking argument.

Nat recursion fed a non-Nat

Negative or fractional input never reaches 0. That's what the Nat in the contract protects against.

Off by one

count-down includes 0; countdown stops at 1; count-up n stops at n−1; (times 3 5) has 4 rows and 6 columns. Test n = 0 and n = 1.

Accumulators

Backwards output

Consing onto an accumulator reverses order. Use plain recursion, or reverse once in the wrapper.

Wrong starting value

The wrapper's initial accumulator: empty, 0, 1, true, or the first element. A product starting at 0 is always 0.

reverse inside the recursion

A red flag for an approach that's too complicated and probably quadratic.

Strings and dictionaries

Character order

Uppercase before lowercase; digits before letters. "Zebra" < "apple", "10" < "9".

Forgetting list->string

If the contract says -> Str, convert the list of characters back.

Spaces are characters

#\space appears in string->list output and counts toward length.

Banned string functions

Only string->list list->string string? string=? string<? (and the other comparisons) plus the char comparisons. No string-length, substring, char-upcase.

Lookup returns the pair

The value is (second (first al)). Failure returns empty, so the contract is (anyof Num empty).

add order

The new pair goes on the front, after deleting any old pair with that key. Expected values in tests must match that order.

5 · Count divisors (wrapper + fixed argument) L04

Write num-divisors: Nat -> Nat that counts how many of 1..n divide n exactly (n ≥ 1). You can only recurse with sub1.

Show solution

Recurse on a second Nat k counting down from n; n itself never changes.

;; How many of 1..k divide n?
;; div-count: Nat Nat -> Nat
(define (div-count n k)
  (cond [(zero? k) 0]
        [(zero? (remainder n k)) (add1 (div-count n (sub1 k)))]
        [else (div-count n (sub1 k))]))
;; num-divisors: Nat -> Nat
;; Requires: n >= 1
(define (num-divisors n) (div-count n n))
(check-expect (num-divisors 12) 6)
(check-expect (num-divisors 7) 2)
(check-expect (num-divisors 1) 1)

8 · All the same? L06 · L07

Write all-same?: (listof Sym) -> Bool, true when every symbol is the same (an empty list counts as true).

Show solution

"All equal" is the same as "every neighbour pair is equal", so use the adjacent-pair shape.

(define (all-same? los)
  (cond [(or (empty? los) (empty? (rest los))) true]
        [(symbol=? (first los) (second los)) (all-same? (rest los))]

22 · Dictionary update and filter L12

Using lookup, add and marks from L12: (a) bump: Str Num AL -> AL adds delta to a key's value, or adds the key with value delta if it's missing. (b) keys-above: Num AL -> (listof Str) lists the keys whose value is greater than k.

Show solution 
(define (bump key delta al)
  (cond [(empty? (lookup key al)) (add key delta al)]
        [else (add key (+ delta (lookup key al)) al)]))
(check-expect (bump "bjones" 10 marks)
              (list (list "bjones" 74) (list "asmith" 87) (list "cwang" 87)))
(check-expect (bump "new" 5 empty) (list (list "new" 5)))

(define (keys-above k al)
  (cond [(empty? al) empty]
        [(> (second (first al)) k) (cons (first (first al)) (keys-above k (rest al)))]
        [else (keys-above k (rest al))]))
(check-expect (keys-above 80 marks) (list "asmith" "cwang"))

lookup runs twice in bump, but on the same arguments in a non-recursive function, so it's only linear, not a blow-up.

23 · Find the bug L07 · L09

Each of these has one bug. Find it and say which input exposes it.

(define (index n lst)                      ; (a)
  (cond [(zero? n) (first lst)]
        [(empty? lst) empty]
        [else (index (sub1 n) (rest lst))]))

(define (ascending? lon)                   ; (b)
  (cond [(or (empty? lon) (empty? (rest lon))) true]
        [(> (first lon) (second lon)) false]
        [else (ascending? (rest (rest lon)))]))

(define (insert n lon)                     ; (c)
  (cond [(empty? lon) empty]
        [(< n (first lon)) (cons n lon)]
        [else (cons (first lon) (insert n (rest lon)))]))
Show solution
  • (a) Base cases in the wrong order: (index 0 empty) calls (first empty). Check empty? first.
  • (b) Skips neighbours: (list 1 5 2 6) returns true because 5 and 2 are never compared. Recur on (rest lon).
  • (c) Inserting into empty loses n: (insert 5 empty) gives empty, and inserting a largest value drops it. Base should be (list n).
